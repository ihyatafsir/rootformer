## 4. The residual, explained

**E1 is 84.36 % of the failing types and 63.53 % of the failing occurrences, and it is not a
bug -- it is the codec's representational limit.**  When `_decompose_greedy` finds no root,
`encode_word` (nrmp_vocab.py:264-268) stores the root slot as `<PARTICLE>`; `decode_word`
(nrmp_vocab.py:312-313) then returns the literal string `<PARTICLE>`.  No decoder change can
recover the word, because nothing about it survives in the tuple: the information was lost at
encode time.  The bucket splits mechanically into:

| E1 stratum | types | occurrences | what it is |
|---|---|---|---|
| `root_ngram_plain_surface_clitic` | 26243 | 104790 | |
| `root_ngram_hamza_or_weak_surface_clitic` | 16488 | 84821 | |
| `no_root_evidence_oov` | 12440 | 124891 | |
| `root_ngram_hamza_or_weak_surface_bare` | 5907 | 43898 | |
| `root_ngram_plain_surface_bare` | 5321 | 24030 | |
| `clitic_root_enclitic_normalized_match` | 2175 | 58902 | |
| `no_root_evidence_oov_definite_article` | 754 | 11991 | |
| `short_or_single_char` | 351 | 8895 | |
| `clitic_plus_closed_particle` | 218 | 35942 | |
| `closed_particle_orthographic_variant` | 101 | 47038 | |
| `clitic_root_enclitic_exact_match_missed` | 79 | 1443 | |
| `clitic_plus_known_token` | 32 | 1076 | |

To decide whether that is "a few mechanical bugs" or "a vocabulary gap", the tokenizer's own
root calculator (`validated_segmentation._candidate_roots` + the tasrif engine, i.e. the same
machinery mode 1 uses to re-segment) was run over a **seeded 1,500-form sample** of E1, across
every clitic split whose affixes actually occur in the word and 20 common awzan:

| outcome | sample | share |
|---|---|---|
| a root that al-'Ayn **attests** generates the stem | 176 | 11.7 % |
| only an **unattested** root the calculator reaches | 424 | 28.3 % |
| **no** root/wazn in the inventory generates the stem | 900 | 60.0 % |

Example recoverable-by-attested-root cases from the probe: `ميلين` = "" + `مول` + `فَعِيل` +
`ين`; `وقياس` = `و` + `قوس` + `فِعَال`; `تسليمها` = `ت` + `سلم` + `فَعِيل` + `ها`.

So of the 547,717 E1 occurrences, roughly **12 % are reachable by better use of the
calculators the release already ships** (an analyzer gap, mechanically fixable but real work),
~28 % require the lexicon/attestation record to admit roots it does not have, and **~60 %
are words for which no root+pattern in the current inventory generates the surface at all**
(proper nouns, loan words, technical vocabulary, rare patterns).  Extrapolated to the whole
bucket that is ~330,000 occurrences of genuinely uncovered vocabulary, not a bug fix.  The
`no_root_evidence_oov*` strata (13194 types / 136882 occ) are the purest form of this: no 3-letter
substring of the word is even in `roots_set`.

The second residual is **E2's OOV part** (302 types / 38,772 occ of `E2` are not the
closed-particle-list bug) and the ~39,900 occurrences of `D1` that the tasrif generator cannot
regenerate from the tuple's own root (`يكن` carries root `كنن`, and `generate(كنن, يَفْعُلُ)`
is `يكنن`, not `يكن`): those need the **root** fixed, not just the missing wazn branch.

## 8. Judgement

* The 26 % token-level failure is **not** one disease.  The three buckets that account for 84.4 % of failing occurrences are: E1 no-analysis (63.5 %), E2 unknown-root (13.7 %), and D1 wazn-unimplemented (7.1 %).
* **Occurrence-weighted**, the answer is encouraging: 25.8 % of failing occurrences are
  reachable by 13 mechanical changes that fit in two functions, and ~26 % of the token gap
  disappears with them.  Most of the remaining token mass is E1, which is a coverage problem.
* **Type-weighted**, the answer is sobering: 84.36 %% of the failing *types* are E1, and only
  ~12 %% of those are reachable by the tokenizer's own attested-root calculator.  The type
  rate cannot exceed ~93 %% without a real lexicon/analyser programme, and cannot exceed
  ~56.4 %% without touching E1 at all.
* The single most valuable *line* is `nrmp_vocab.py:312-313` combined with `:166`: the
  control-token echo and the disjoint particle inventory.  The single most valuable *rule*
  is already written in the repo at `morphemic_tokenizer_v12_arabic.py:847-852` and simply
  never called by `decode_word`.
